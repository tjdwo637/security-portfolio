### 취약점 관리 · 침해 대응

**취약점 점검 자동화 도구 개발**
KISA 주요정보통신기반시설 기술적 취약점 분석 가이드의 Windows Server 점검 항목을 스크립트로 옮기고, 외부 노출 여부를 확인하는 자체 점검 항목을 추가했습니다. NVD, CISA KEV, EPSS를 연동해 발견한 취약점이 실제로 악용되고 있는지까지 함께 판단하도록 구성했고, SCA 도구와 호스트 스캐너를 오케스트레이션해 한 번의 실행으로 점검이 끝나도록 만들었습니다. 결과는 요약 / 상세 / 포트 현황 / 조치 방안 네 개 시트로 산출됩니다. 점검 기준이 다른 환경에서도 항목만 교체하면 그대로 쓸 수 있는 구조입니다.

`Python` `NVD API v2` `OSV.dev` `CISA KEV` `EPSS` `nmap` `SCA`

**RDP 침해 시도 대응 및 원격접속 통제 정책 수립**
외부에서 유입되는 RDP 접근 시도가 늘어 처음에는 포트 변경으로 급히 대응했습니다. 그런데 바뀐 포트가 기존 관제 룰과 관리 도구에 반영되지 않아 오히려 가시성이 떨어졌고 사용자 불편도 생겨, 설정을 되돌렸습니다. 이후 로그로 접근 시도의 출발지와 계정 패턴을 분석해 포트를 숨기는 것보다 접속 허용 대상을 좁히는 편이 근본 조치라고 판단했고, 허용 IP 화이트리스트와 엔드포인트 정책으로 다시 설계했습니다. 이 일을 겪은 뒤로 급한 위협일수록 분석과 영향 범위 확인을 먼저 하도록 절차를 굳혔습니다.

**접근통제 정책 재설계**
외부에서 제한 없이 접근 가능하던 개발 관리 시스템의 As-Is 상태를 정리하고, 허용 대상을 담당자와 사내망으로 한정하는 To-Be 정책을 설계했습니다. 원격 근무자는 VPN을 경유하도록 강제하고, 협력사 접근은 출발지 기준으로 개별 허용하는 방식으로 전환했습니다.

**무선 네트워크 점검 절차 정립**

## Research & Reference

### 점검 기준 문서 체계화
연도별 KISA 기술적 취약점 분석·평가 가이드와 관리적·물리적 보안 가이드, NIST SP 800-30(위험관리) 및 SP 800-82(제어시스템 보안)를 항목 단위로 정리해 색인화했습니다. 기술 항목 380여 개, 관리 항목 110여 개, 물리 항목 18개 규모의 마스터 인덱스를 만들어 점검 도구와 규정 개정의 기준으로 쓰고 있습니다.

### 로그 수집 · 분석 기반 설계
Sysmon과 SIEM(Graylog) 기반 로그 수집 체계를 설계했습니다. 방화벽과 NAC의 Syslog 파싱 규칙을 작성했고, 메일 인증(SPF / DKIM / DMARC)과 시각 동기화(NTP) 표준화를 로드맵에 두고 단계적으로 적용하고 있습니다.
